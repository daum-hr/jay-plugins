# 되돌리기 (undo)

비개발자를 위한 복구. 사용자는 `revert`와 `restore`와 `stash`를 구분하지 않는다 —
"되돌려줘"라고 말한다. 이 스킬이 상황을 나누고, 상황마다 **가장 안전한 방법 하나만** 쓴다.

먼저 `${CLAUDE_PLUGIN_ROOT}/references/git-collab.md`를 읽는다 — 어휘(§1), 카드(§2),
안전 기준선(§5).

**이 스킬의 약속**: 되돌린 뒤에도 "없어진 것 같은 작업"이 실제로 어디에 있는지 항상
이름을 대서 알려준다. 사라졌다는 느낌을 남기지 않는 것이 핵심이다.

## Step 1: 조용히 확인

```bash
git status --porcelain 2>&1
git rev-parse --abbrev-ref HEAD 2>&1
git log --oneline -5 2>&1
git branch -r --contains HEAD 2>/dev/null    # 직전 저장이 이미 올라갔나
git stash list 2>&1
```

## Step 2: 어떤 상황인지 묻는다

사용자 말로 이미 분명하면 건너뛴다. 아니면 AskUserQuestion:

> "어떤 걸 되돌리고 싶으세요?
> ① 아직 저장(commit) 안 한 변경 버리기
> ② 방금 한 저장을 고치거나 무르기
> ③ 이미 팀에 올린(push) 저장 되돌리기
> ④ 실수로 main에 저장했어요
> ⑤ 지금 작업을 잠깐 치워두기 (보관함)
> ⑥ 잘 모르겠어요"

⑥ → `/jay-skills:status`를 먼저 돌리고 다시 묻는다.

## ① 저장 안 한 변경 버리기

되돌릴 수 없는 작업이므로 **반드시 두 단계**로 간다.

1. 어떤 파일의 무엇이 사라지는지 한 줄씩 보여준다 (파일명 + 변경 요약).
2. 더 안전한 대안을 먼저 제시한다:

   > "버리는 대신 보관함에 치워두면 나중에 그대로 꺼낼 수 있어요.
   > ① 보관함에 치워두기 (권장 — 되돌릴 수 있어요)
   > ② 정말 버리기 — 이 {n}개 파일의 변경이 **영구히 사라집니다**
   > ③ 그만두기"

② 를 고르면 파일을 하나씩 지정해서만 되돌린다:

```bash
git restore --source=HEAD --staged --worktree -- {파일1} {파일2}
```

`--source=HEAD --staged --worktree`를 반드시 함께 준다. 그냥 `git restore -- {파일}`은
**저장 대기 상태(index)** 기준으로 되돌리기 때문에, 이미 저장 대기에 올라간 변경은
남는다 — 사용자에게는 "영구히 사라집니다"라고 말해 놓고 실제로는 일부가 살아남는
어긋남이 생긴다.

폴더 전체나 `.` 같은 통짜 형태는 쓰지 않는다 — 의도하지 않은 파일까지 날아간다.

## ② 방금 한 저장 고치기 / 무르기

`git branch -r --contains HEAD` 결과로 갈린다.

**아직 안 올렸으면** (내 컴퓨터에만 있음):

> "아직 팀에 안 올린 저장이라 안전하게 고칠 수 있어요.
> ① 저장 메시지만 고치기 / 빠뜨린 파일 추가하기
> ② 저장 자체를 무르기 (내용은 그대로 두고 '저장'만 취소 — 다시 고쳐서 저장할 수 있어요)
> ③ 그만두기"

- ① → `git commit --amend`
- ② → `git reset --soft HEAD~1` — 작업 내용은 하나도 사라지지 않고 "저장 대기" 상태로
  돌아간다. 이 점을 반드시 말한다.

**이미 올렸으면**: 고치지 않는다. 이유를 설명하고 ③으로 넘긴다.

> "이 저장은 이미 팀 저장소에 올라가서 동료 컴퓨터에도 갔을 수 있어요. 그래서 이력을
> 고치는 대신, **반대 내용의 새 저장**을 만들어서 원래대로 되돌립니다. 기록이 남아서
> 나중에 무슨 일이 있었는지 알 수 있어요."

## ③ 이미 올린 저장 되돌리기

되돌릴 저장을 쉬운 말로 보여주고 확인받은 뒤:

```bash
git revert {커밋}
```

한 번에 하나씩만 한다. 끝나면 "되돌린 내용도 팀에 알려야 해요" 하고
`/jay-skills:push`를 권한다. 충돌이 나면 `/jay-skills:fix-conflict`.

## ④ 실수로 main에 저장했을 때

**아직 안 올렸으면** (대부분의 경우):

1. 먼저 작업을 안전한 곳에 담는다 — `git branch {feature/구조-이름}` (지금 위치에서
   갈래만 만드는 것이라 아무것도 움직이지 않는다).
2. 그 갈래에 저장이 들어갔는지 확인한 뒤에만 main을 정리한다:
   `git reset --keep origin/main`. `--keep`은 저장 안 된 변경이 있으면 스스로 거부한다 —
   거부하면 그대로 두고 알린다.
3. 팀 저장소 주소를 모르거나 `origin/main`이 없으면 **정리하지 않는다**:
   "작업은 새 갈래 `{이름}`에 안전하게 있어요. main 정리는 팀과 함께 보는 게
   좋겠습니다."

**이미 main에 올라갔으면**: 이력을 손대지 않는다. `git revert`로 되돌리는 새 저장을
만들고, **즉시 팀에 알리도록 안내한다** — 동료가 이미 받아갔을 수 있다.

## ⑤ 잠깐 치워두기 (보관함)

```bash
git stash push -m "{사용자 말로 만든 한 줄 설명}"
```

끝나면 꺼내는 법을 반드시 알려준다:

> "치워뒀어요: '{설명}'. 나중에 '보관한 거 꺼내줘'라고 하시면 그대로 복원합니다.
> 컴퓨터를 껐다 켜도 남아 있어요."

꺼낼 때는 `git stash pop`, 충돌 나면 `/jay-skills:fix-conflict`.

## 마무리 카드

`git-collab.md` §2 형식으로 끝내되, **"없어진 것처럼 보이는 작업이 지금 어디 있는지"를
반드시 한 줄로 명시한다**. 예: "되돌린 작업은 `feature/구조-공지사항` 갈래에 그대로
있어요" / "치워둔 작업은 보관함에 '표 정렬 작업 중'이라는 이름으로 있어요".

## 절대 하지 않는 것

- `git reset --hard`, `git clean -f` — 저장 안 된 작업이 말없이 사라진다.
- force push.
- 이미 올린 저장에 amend / rebase.
- 갈래 삭제, 보관함 비우기(`stash drop` / `stash clear`).
- 파일 지정 없는 통짜 `restore` / `checkout .`.
- 되돌릴 수 없는 작업을 확인 없이 실행하기.
