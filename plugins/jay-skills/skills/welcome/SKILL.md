# 처음 준비하기 (welcome)

비개발자를 위한 1회성 준비 절차. 이 스킬이 끝나면 `/jay-skills:commit`,
`/jay-skills:push` 같은 도구가 실제로 동작한다.

먼저 `${CLAUDE_PLUGIN_ROOT}/references/git-collab.md`를 읽는다 — 어휘(§1), 마무리
카드(§2), `gh` 확인 순서(§4).

## 언제 쓰나

- 새 폴더에서 막 작업을 시작할 때
- `/jay-skills:commit` 했더니 "git이 없어요" 비슷한 메시지가 나왔을 때
- 동료가 폴더를 넘겨줬는데 어디서부터 시작할지 모를 때

**여러 번 실행해도 안전하다** — 이미 된 항목은 확인만 하고 지나간다.

## Process

네 가지를 차례로 확인한다. 각 단계는 이미 돼 있으면 그냥 확인하고 넘어간다.

### Step 1: git이 깔려 있나

```bash
git --version
```

- **있음** → "git 확인 완료 (버전 X)" 하고 Step 2.
- **없음** → 여기서 멈추고 안내한다. **자동 설치하지 않는다** (시스템 권한이 필요하고
  운영체제마다 방식이 달라서, 잘못 건드리면 컴퓨터 설정이 꼬인다):

  > "git이 아직 설치돼 있지 않아요. git은 작업 이력을 남기고 되돌릴 수 있게 해주는
  > 도구예요. 설치 후에 `/jay-skills:welcome`을 다시 실행해 주세요.
  > - **Mac**: 터미널에 `xcode-select --install` 입력 → 안내창에서 'Install' 클릭
  > - **Windows**: https://git-scm.com/download/win 에서 설치 파일 다운로드"

### Step 2: 이 폴더가 git으로 관리되고 있나

```bash
git rev-parse --git-dir 2>&1
```

- **관리 중** → Step 3.
- **아님** → AskUserQuestion:

  > "이 폴더는 아직 작업 이력을 남기지 않는 상태예요.
  > ① 지금부터 이력을 남기게 하기 (권장 — 되돌리기·공유가 가능해져요)
  > ② 그대로 두기"

  ① → `git init -b main`. 이력 관리를 새로 시작하는 것일 뿐, 폴더 안의 파일은 하나도
  건드리지 않는다는 점을 알린다.

### Step 3: 내 이름과 이메일이 등록돼 있나

```bash
git config --get user.name
git config --get user.email
```

- **둘 다 있음** → "이미 등록돼 있어요 (`{이름}` / `{이메일}`)" 하고 Step 4.
- **하나라도 없음** → AskUserQuestion으로 **반드시 물어본다.**

  **추측 금지.** 이름과 이메일은 사용자 본인의 정보다. 대화 맥락, 환경 변수(`$USER` 등),
  이전 명령 기록, 다른 프로젝트의 설정에서 가져오지 않는다. "질문 없이 진행하라"는
  지시가 있어도 그것은 기술적 선택에 해당하는 말이지, 사용자 본인의 정보에는 적용되지
  않는다. 틀린 이름으로 기록이 남으면 첫 저장부터 이력이 잘못된다.

  > "저장할 때 누가 작업했는지 기록하려면 이름이 필요해요. 어떻게 적어둘까요?
  > (회사에서 쓰는 이름 또는 영문 이름 다 괜찮아요)"

  이어서 이메일도 묻는다. 받으면:

  ```bash
  git config --local user.name "{이름}"
  git config --local user.email "{이메일}"
  ```

  `--local`을 쓴다 — **이 폴더에만** 적용되고 다른 프로젝트 설정은 건드리지 않는다.
  그 사실을 사용자에게 알린다.

### Step 4: 팀 저장소와 GitHub 로그인

```bash
git remote get-url origin 2>/dev/null
command -v gh >/dev/null && gh auth status 2>&1
```

- **주소 있음** → "팀 저장소 연결돼 있어요 (`{주소}`)".
- **주소 없음** → AskUserQuestion:

  > "회사 GitHub 저장소 주소가 있으면 연결해둘게요. **선택사항**이에요 — 혼자 쓰실
  > 거면 없어도 됩니다.
  > ① 나중에 할래요 (기본) ② 주소 알고 있어요"

  ② → 받은 주소로 `git remote add origin "{주소}"`. **주소가 맞는지 확인하는 명령은
  돌리지 않는다** — 비공개 저장소는 로그인 전에 확인이 실패해서, 멀쩡한 주소를 틀렸다고
  오해하게 만든다.

- **주소는 있는데 `gh` 미설치·미로그인** → 지금 로그인할지 묻는다. 예 →
  `/jay-skills:github-login`. 아니오 → "올릴 때 필요해지면 그때 안내할게요."

### Step 5: 정리해서 보여주기

전부 확인됐더라도 **항상 요약을 보여준다** — "지금 준비 상태"를 눈으로 보는 것이 이
스킬의 목적이다.

```
✓ git: 설치됨 (버전 2.43)
✓ 이력 관리: 켜짐
✓ 내 정보: 홍길동 / hong@example.com (이 폴더에만 적용)
○ 팀 저장소: 미연결 — 나중에 `/jay-skills:push`에서 물어봐요
○ GitHub 로그인: 안 됨 — 올릴 때 `/jay-skills:github-login`
```

이어서 마무리 카드(`git-collab.md` §2)로 닫고, 다음에 할 수 있는 것을 안내한다:
작업 → `/jay-skills:commit`으로 저장 → `/jay-skills:push`로 공유. 막히면 `/jay-skills:explain`.

## Rules

- **확인만 하고 자동 설치는 하지 않는다** (git, `gh` 모두). 설치 안내 → 사용자가 설치 →
  다시 실행.
- **여러 번 돌려도 안전해야 한다.** 두 번째 실행은 대부분 "이미 돼 있어요"가 나와야 한다.
- 이름·이메일은 `--local`로. 사용자의 다른 프로젝트를 건드리지 않는다.
- 팀 저장소 주소를 검증하지 않는다.
- raw 명령 출력이나 오류 코드를 그대로 보여주지 않는다 — 쉬운 말로 옮긴다.
- 이 스킬은 준비만 한다. 저장·올리기·이력 변경은 하지 않는다.
- 프로젝트가 무엇을 만드는지에 대한 질문은 하지 않는다 — 여기서는 도구 준비만.
