# 처음 준비하기 (welcome)

비개발자를 위한 1회성 준비 절차. 이 스킬이 끝나면 `/jay-skills:commit`,
`/jay-skills:push` 같은 도구가 실제로 동작한다.

먼저 `${CLAUDE_PLUGIN_ROOT}/references/git-collab.md`를 읽는다 — 어휘(§1), 마무리
카드(§2), `gh` 확인 순서(§4).

## 언제 쓰나

- 새 폴더에서 막 작업을 시작할 때
- **동료가 팀 저장소 주소(링크)를 줬는데 어떻게 받아오는지 모를 때** — clone(팀
  저장소를 이력까지 통째로 복사해 오는 것)까지 여기서 한다
- 새 컴퓨터에서 처음 시작할 때
- `/jay-skills:commit` 했더니 "git이 없어요" 비슷한 메시지가 나왔을 때
- 동료가 폴더를 넘겨줬는데 어디서부터 시작할지 모를 때

**여러 번 실행해도 안전하다** — 이미 된 항목은 확인만 하고 지나간다.

## Process

다섯 가지를 차례로 확인한다. 각 단계는 이미 돼 있으면 그냥 확인하고 넘어간다.
(팀 저장소를 clone하는 경우에만 Step 2.5가 추가로 끼어든다.)

### Step 1: 필요한 프로그램이 깔려 있나 (git · gh)

두 가지를 나란히 확인한다. **막는 것은 git 하나뿐이다.**

```bash
git --version 2>&1
command -v gh >/dev/null && gh --version 2>&1 || echo gh-missing
```

**git — 없으면 여기서 멈춘다.** 커밋 자체가 안 되기 때문이다. **자동 설치하지 않는다**
(시스템 권한이 필요하고 운영체제마다 방식이 달라서, 잘못 건드리면 컴퓨터 설정이 꼬인다):

> "git이 아직 설치돼 있지 않아요. git은 작업 이력을 남기고 되돌릴 수 있게 해주는
> 도구예요. 설치 후에 `/jay-skills:welcome`을 다시 실행해 주세요.
> - **Mac**: 터미널에 `xcode-select --install` 입력 → 안내창에서 'Install' 클릭
> - **Windows**: https://git-scm.com/download/win 에서 설치 파일 다운로드"

**gh — 없어도 멈추지 않는다.** 설치 방법만 알려주고 **그대로 다음 단계로 간다**:

> "`gh`(GitHub 연결 도구)는 아직 없네요. **커밋까지는 gh 없이 됩니다** — 팀 저장소와
> 주고받을 때(push·pull·PR) 필요해요. 나중에 설치하셔도 됩니다.
> - **Mac**: `brew install gh` (brew가 없으면 https://cli.github.com 에서 설치 파일)
> - **Windows**: `winget install GitHub.cli`"

gh가 없다는 사실은 Step 4와 Step 5에서 한 번 더 그대로 반영한다 — 없는 것을 있는 것처럼
넘어가지 않는다.

### Step 2: 이 폴더가 어떤 상태인가

```bash
git rev-parse --git-dir 2>&1
ls -A | head -5              # 폴더가 비어 있나
```

**관리 중** → Step 3.

**git이 아닌데 폴더에 파일이 있음** → 내 작업이 이미 여기 있는 상태다. AskUserQuestion:

> "이 폴더는 아직 작업 이력을 남기지 않는 상태예요.
> ① 지금부터 이력을 남기게 하기 (권장 — 되돌리기·공유가 가능해져요)
> ② 그대로 두기"

① → `git init -b main`. 이력 관리를 새로 시작하는 것일 뿐, 폴더 안의 파일은 하나도
건드리지 않는다는 점을 알린다.

**git이 아니고 폴더도 비어 있음** → **여기서 `git init`을 먼저 권하지 않는다.** 빈 폴더에
있는 사람은 대개 *팀 저장소를 clone하려는* 것이지 새로 만들려는 게 아니다. 먼저 묻는다:

> "지금 폴더가 비어 있어요. 어느 쪽인가요?
> ① 동료가 준 주소로 팀 저장소 clone하기 (주소나 링크를 갖고 계시면 이쪽)
> ② 여기서 새 작업을 시작하기
> ③ 그대로 두기"

② → 위 `git init -b main`. ③ → Step 3으로.
① → 아래 **Step 2.5**로 간다.

### Step 2.5: 팀 저장소 clone (①을 골랐을 때만)

**순서가 핵심이다 — 로그인이 먼저, clone이 나중이다.** 비공개 저장소는 로그인 없이
받아올 수 없고, 그때 나오는 에러는 "주소가 틀렸다"처럼 보여서 사용자를 엉뚱한 곳으로
보낸다.

**① 주소를 받고 목표 서버를 도출한다.**

```bash
# 사용자가 준 주소(https://.../owner/repo 또는 owner/repo)에서 호스트를 뽑는다
HOST=$(echo "{받은 주소}" | sed -E 's#^[a-z]+://##; s#^[^@/]*@##; s#[:/].*$##')
case "$HOST" in *.*) ;; *) HOST=github.com ;; esac   # owner/repo 형태면 github.com
```

주소가 `github.com`이 아니면 그 사실을 알린다: "회사가 직접 운영하는 GitHub
서버(`{HOST}`)네요 — github.com과는 별개라 로그인도 따로 합니다."

**② `gh`가 없으면 여기서 멈춘다.** Step 1에서 안내한 설치 방법을 다시 보여준다. 커밋은
gh 없이 되지만 **clone은 안 된다** — 이 차이를 분명히 말한다.

**③ 로그인 확인. 미로그인이면 clone 전에 로그인부터.**

```bash
gh auth status --hostname "$HOST" 2>&1
```

미로그인이면 `/jay-skills:github-login`으로 넘긴다. **목표 서버 `$HOST`를 함께 넘긴다** —
그 스킬은 보통 `origin`에서 서버를 찾는데 지금은 `origin`이 없다.

**④ clone한다.** 지금 폴더가 비어 있으므로 **이 폴더 안으로 바로** 받는다 — 하위 폴더로
받으면 사용자가 Claude Code를 다시 열어야 해서 흐름이 끊긴다.

```bash
gh repo clone "{owner/repo}" . 2>&1
```

`gh repo clone`을 쓴다(기술 결정). `gh`가 자기 로그인을 그대로 쓰기 때문에, 자격 설정이
아직 안 끝났어도 비공개 저장소가 받아진다.

실패하면 `git-collab.md` §3 번역표로 분류한다 — **맨 윗줄(연결 실패)부터** 본다.
네트워크면 VPN 안내 후 정지, 권한이면 "저장소를 만든 사람에게 초대를 요청" 문장을 준다.

성공하면 무엇이 생겼는지 눈으로 보여주고 Step 3으로 간다:

> "받아왔어요. 이 폴더에 파일 {n}개가 들어왔고, 지금부터 팀 저장소와 이어져 있습니다."

### Step 3: 내 이름과 이메일이 등록돼 있나

```bash
git config --get user.name
git config --get user.email
```

- **둘 다 있음** → "이미 등록돼 있어요 (`{이름}` / `{이메일}`)" 하고 Step 4.
- **하나라도 없음** → AskUserQuestion으로 **반드시 물어본다.**

  **추측 금지.** 이름과 이메일은 사용자 본인의 정보다. 대화 맥락, 환경 변수(`$USER` 등),
  이전 명령 기록, 다른 프로젝트의 설정에서 가져오지 않는다. "질문 없이 진행하라"는
  지시가 있어도 그것은 기술적 선택에 해당하는 말이지, 사용자 본인의 정보에는 적용되지
  않는다. 틀린 이름으로 기록이 남으면 첫 커밋부터 이력이 잘못된다.

  > "커밋할 때 누가 작업했는지 기록하려면 이름이 필요해요. 어떻게 적어둘까요?
  > (회사에서 쓰는 이름 또는 영문 이름 다 괜찮아요)"

  이어서 이메일도 묻는다. 받으면:

  ```bash
  git config --local user.name "{이름}"
  git config --local user.email "{이메일}"
  ```

  `--local`을 쓴다 — **이 폴더에만** 적용되고 다른 프로젝트 설정은 건드리지 않는다.
  그 사실을 사용자에게 알린다.

### Step 4: 팀 저장소와 GitHub 로그인

**① 팀 저장소 주소부터 본다. 목표 서버는 거기서 나온다.**

```bash
git remote get-url origin 2>/dev/null
```

```bash
HOST=$(git remote get-url origin 2>/dev/null \
       | sed -E 's#^[a-z]+://##; s#^[^@/]*@##; s#[:/].*$##')
[ -n "$HOST" ] || HOST=github.com
```

- **주소 있음** → "팀 저장소 연결돼 있어요 (`{주소}`)". 주소가 `github.com`이 아니면 그
  사실을 말한다: "회사가 직접 운영하는 GitHub 서버(`{HOST}`)예요 — github.com과는 별개의
  서버라, 로그인도 따로 합니다."
- **주소 없음** → AskUserQuestion:

  > "회사 GitHub 저장소 주소가 있으면 연결해둘게요. **선택사항**이에요 — 혼자 쓰실
  > 거면 없어도 됩니다.
  > ① 나중에 할래요 (기본) ② 주소 알고 있어요"

  ② → 받은 주소로 `git remote add origin "{주소}"`. **주소가 맞는지 확인하는 명령은
  돌리지 않는다** — 비공개 저장소는 로그인 전에 확인이 실패해서, 멀쩡한 주소를 틀렸다고
  오해하게 만든다.

**② 로그인 판정은 `--hostname $HOST` 결과로만 한다.**

```bash
gh auth status --hostname "$HOST" 2>&1     # 판정 근거
gh auth status 2>&1                        # 전체 그림 (참고용)
```

옵션 없는 `gh auth status`만 보고 판정하면 **다른 서버에 로그인돼 있는 것을 "로그인됨"으로
오판한다.** 회사 서버와 github.com은 별개이므로, github.com에 로그인돼 있어도 회사 서버는
미로그인일 수 있다. 판정에는 반드시 `--hostname`을 붙인 쪽을 쓴다.

**③ 다음 행동은 gh 설치 여부로 갈린다.**

- **gh 없음** → **질문하지 않는다.** 사실만 서술하고 넘어간다: "`{HOST}` 로그인은 `gh`를
  설치한 뒤에 확인할 수 있어요. 커밋은 지금도 됩니다." (질문을 띄우면 사용자가 고를 수
  있는 답이 없어 막다른 길이 된다.)
- **gh 있음 + `$HOST` 로그인돼 있음** → "`{HOST}` 에 `{계정}` 계정으로 로그인돼 있어요."
- **gh 있음 + `$HOST` 미로그인** → 여기서만 묻는다: "지금 로그인해 둘까요? 브라우저 한
  번 여는 걸로 끝나요. ① 지금 할게요 ② 나중에 (push할 때 다시 안내해 드려요)"
  ① → `/jay-skills:github-login`.
- **팀 저장소 주소 자체가 없음** → 로그인 확인을 건너뛴다. 확인할 목표 서버가 없다.
  (받아올 저장소가 있는 사람은 Step 2에서 이미 갈라져 나갔다.)

### Step 5: 정리해서 보여주기

전부 확인됐더라도 **항상 요약을 보여준다** — "지금 준비 상태"를 눈으로 보는 것이 이
스킬의 목적이다. **다섯 줄 전부 낸다** (없는 항목은 `○` 로 낸다 — 줄 자체를 빼지 않는다):

```
✓ git: 설치됨 (버전 2.43)
✓ gh (GitHub 연결 도구): 설치됨 (버전 2.62)
✓ 이력 관리: 켜짐
✓ 내 정보: 홍길동 / hong@example.com (이 폴더에만 적용)
✓ 팀 저장소: github.example.com/team/repo (사내 GitHub)
○ github.example.com 로그인: 안 됨 — push할 때 `/jay-skills:github-login`
```

- 팀 저장소 줄에는 **호스트 종류**를 함께 적는다: `(사내 GitHub)` / `(github.com)`.
- 로그인 줄의 제목은 `$HOST` 를 그대로 쓴다 — "GitHub 로그인"이라고만 쓰면 어느 서버
  이야기인지 알 수 없다.

이어서 마무리 카드(`git-collab.md` §2)로 닫고, 다음에 할 수 있는 것을 안내한다:
작업 → `/jay-skills:commit` → `/jay-skills:push`로 공유. 막히면 `/jay-skills:explain`.

**이 폴더가 실행할 앱을 갖고 있으면 한 가지만 더 묻는다.** 판정은 두 가지 중 하나면
충분하다 — `package.json`에 `scripts.dev` 또는 `scripts.start`가 있거나, README에 개발환경
안내 섹션이 있거나.

```bash
[ -f package.json ] && grep -qE '"(dev|start)"[[:space:]]*:' package.json && echo has-app
grep -qiE '^#+.*(개발환경|시작하기|Getting Started)' README.md 2>/dev/null && echo has-doc
```

둘 다 아니면 **이 질문 자체를 건너뛴다.** 해당하면 AskUserQuestion:

> "이어서 개발환경까지 준비해 드릴까요? Node 확인 → 라이브러리 설치 → 서버 켜기까지 해서
> 브라우저로 화면을 볼 수 있게 돼요.
> ① 네, 이어서 해주세요 ② 나중에 — '서버 켜줘'라고 하시면 언제든지"

① → `/jay-skills:dev-up`. 설치가 필요한 일은 **전부 그쪽에서 다시 동의를 받는다** — 이
스킬은 여전히 아무것도 설치하지 않는다.

## Rules

- **확인만 하고 자동 설치는 하지 않는다** (git, `gh` 모두). 설치 안내 → 사용자가 설치 →
  다시 실행.
- **빈 폴더에서 `git init`을 먼저 권하지 않는다.** clone하려는 것인지 새로 시작하려는
  것인지를 먼저 묻는다 (Step 2).
- **clone은 로그인 뒤에 한다.** 순서를 뒤집으면 비공개 저장소에서 나는 에러가
  "주소가 틀렸다"처럼 보여 사용자를 엉뚱한 곳으로 보낸다 (Step 2.5).
- **git 없음만 멈춤 사유다.** gh 없음은 안내 후 계속 진행한다.
- **여러 번 돌려도 안전해야 한다.** 두 번째 실행은 대부분 "이미 돼 있어요"가 나와야 한다.
- 이름·이메일은 `--local`로. 사용자의 다른 프로젝트를 건드리지 않는다.
- 팀 저장소 주소를 검증하지 않는다.
- 로그인 판정은 `gh auth status --hostname $HOST` 로만 한다.
- raw 명령 출력이나 오류 코드를 그대로 보여주지 않는다 — 쉬운 말로 옮긴다.
- 이 스킬은 준비만 한다. 커밋·push·이력 변경은 하지 않는다. clone은 예외지만,
  그것도 새로 만드는 게 아니라 팀 저장소를 그대로 복사해 오는 것이다.
- 프로젝트가 무엇을 만드는지에 대한 질문은 하지 않는다 — 여기서는 도구 준비만.
