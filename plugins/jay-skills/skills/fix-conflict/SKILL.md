# 충돌 정리하기 (fix-conflict)

비개발자를 위한 충돌 해결. 첫 문장은 언제나 안심시키는 것부터:

> "충돌은 고장이 아니에요. 같은 곳을 두 사람이 다르게 고쳐서, **어느 쪽을 남길지
> 사람이 정해달라**는 요청입니다. 하나씩 같이 고르면 됩니다."

먼저 `${CLAUDE_PLUGIN_ROOT}/references/git-collab.md`를 읽는다 — 어휘(§1), 카드(§2),
안전 기준선(§5), 자동 처리 대상(§6), 질문 문구 재검토(§7).

이 스킬은 git 상태를 바꾸므로 **마무리 카드를 생략하지 않는다** (§2).

## Step 0: 지금 어떤 상태인지 판정

```bash
ls .git/MERGE_HEAD .git/rebase-merge .git/rebase-apply 2>/dev/null
git diff --name-only --diff-filter=U 2>&1
git status --porcelain 2>&1
```

- **`MERGE_HEAD` 있음** → 합치는 중. 이 스킬의 기본 경로.
- **`rebase-merge` / `rebase-apply` 있음** → 우리가 시작하지 않은 재정렬 작업이다.
  **이어서 진행하지 않는다.** AskUserQuestion:

  > "진행 중인 '이력 재정렬(rebase)' 작업이 있는데, 이건 이 도구가 시작한 게 아니에요.
  > ① 취소하고 원래 상태로 되돌리기 (권장 — 아무것도 잃지 않아요)
  > ② 그대로 두고 팀에 물어보기"

  ① → `git rebase --abort`. **`--continue`는 어떤 경우에도 쓰지 않는다.**
- **둘 다 없는데 파일에 충돌 표시(`<<<<<<<`)가 남아 있음** → 중간에 멈춘 상태. 파일
  내용을 정본으로 보고 조각별 정리만 진행한다 (되돌릴 대상이 없으므로 "그만두기"
  선택지는 "그대로 두기"로 바꿔 제시).
- **아무 충돌도 없음** → "정리할 충돌이 없어요." 하고 `/jay-skills:status`로 안내.

## Step 1: 규모 확인 — 혼자 정리하면 안 되는 경우

아래 중 **하나라도** 해당하면 조각별 정리를 시작하지 않고 에스컬레이션한다:

- 충돌 파일이 4개 이상, 또는 한 파일 안의 충돌 조각이 9개 이상
- 잘못 merge하면 시스템이 멈추는 파일: 이름에 `migration`이 들어간 파일, `settings.json`,
  `package.json`의 의존성 부분, `.env`로 시작하는 파일, 인증(`auth`) 관련 파일
- 그림·PDF 같은 binary 파일 (사람이 조각으로 고를 수 없다)

에스컬레이션 문구:

이때 **누구에게 물어야 하는지까지 알려준다.** 겹치는 파일을 마지막에 고친 동료를 찾는다:

```bash
git log -1 --format='%an' -- {충돌 파일}
```

> "이번 충돌은 혼자 정리하지 않는 게 안전해요. 이유: {해당 사유}.
> 이 부분을 최근에 고친 사람은 **{이름}** 님이에요 — 같이 보시는 걸 권합니다.
> 지금 선택하실 수 있어요.
> ① 충돌 전 상태로 되돌리기 — pull하기 전, 오늘 작업 시작했을 때와 같은 상태로
>    돌아갑니다. 내 커밋도 동료 커밋도 사라지지 않아요. (권장 — 나중에 같이 다시 pull하면 돼요)
> ② 이 상태 그대로 두고 팀에 물어보기
>
> {이름} 님께 이렇게 전해 주세요:
> `{현재 브랜치} 에서 pull하다가 겹치는 부분이 생겼어요. 파일: {파일 목록}. 같이 봐주실 수 있을까요?`"

## Step 1.5: 사람이 고를 필요 없는 것은 알아서 정리

`package-lock.json` · `yarn.lock` · `pnpm-lock.yaml` 은 동료 버전을 그대로 받는다:

```bash
git checkout --theirs -- {잠금파일}
git add {잠금파일}
```

묻지 않되, **정했다는 사실은 알린다**: "잠금 파일은 자동으로 정리했어요 — 사람이 고를
내용이 아니라서요."

## Step 2: 파일마다, 조각마다 고르기

충돌 파일을 하나씩 연다. 파일 안의 `<<<<<<<` / `=======` / `>>>>>>>` 구간이 조각이다.
조각마다:

1. **이 부분이 무슨 역할인지 두 줄로 설명한다.** 예: "이 부분은 공지사항 목록 화면
   맨 위에 보이는 제목 문구예요."
2. **양쪽을 나란히 보여준다.** 각 10줄 이내로 자르고, 라벨은 이렇게 고정한다:
   - **내 버전** — 이 컴퓨터에서 작업한 내용
   - **동료 버전** — 팀 저장소에 올라와 있는 내용

   (stash에서 꺼내다 난 충돌이면 "치워뒀던 내 작업" / "그 사이 받아온 내용"으로 바꾼다.)
3. AskUserQuestion:

   > "어느 쪽을 남길까요?
   > ① 내 버전 ② 동료 버전 ③ 둘 다 필요해요 (두 내용을 이어서 한 문장으로 정리해 드릴게요)
   > ④ 잘 모르겠어요"

   - ③ → 두 내용을 이어서 정리한 결과를 보여주고 "이대로 할까요?" 한 번 더 확인.
     이것은 merge가 아니라 **글을 이어 붙이는 일**이다 — "합치기"라고 부르지 않는다
     (`git-collab.md` §1).
   - ④ → 그 조각은 미정으로 남기고 다음으로. **추측해서 고르지 않는다.**
4. 파일이 여러 개면 진행 상황을 알린다: "파일 2/3 정리 중이에요."

정리가 끝났는데 **미정 조각이 하나라도 남아 있으면** Step 1의 에스컬레이션으로 간다
(되돌리기 또는 팀 문의). 미정을 임의로 채워서 끝내지 않는다.

## Step 3: 검사하고 마무리 커밋

```bash
grep -rn '^<<<<<<<' . --exclude-dir=.git 2>/dev/null
```

충돌 표시가 하나라도 남아 있으면 **여기서 멈춘다** — 그 상태로 커밋되면 화면이 깨진다.
남은 위치를 알려주고 Step 2로 돌아간다.

깨끗하면:

```bash
git add {정리한 파일들}
git commit -m "merge: 동료 작업과 merge (충돌 {n}곳 정리)"
```

## Step 4: 마무리 카드

```
### 지금 상태
- 충돌 {n}곳을 정리해서 merge했어요. 동료 작업과 내 작업이 한 흐름이 됐습니다.
- 커밋 안 된 변경: 없음

### 다음에 할 수 있는 것
- merge 결과를 팀에 push하려면: `/jay-skills:push`
- 화면이 제대로 나오는지 확인해 보세요 (merge 뒤에는 눈으로 보는 확인이 가장 확실해요)
- 잘 모르겠으면: 여기서 멈추고 팀에 물어보기 — 지금 상태 그대로 두면 아무것도 망가지지 않아요
```

## 언제든 "그만할래요"

모든 질문에서 중단할 수 있다. 중단 = `git merge --abort` 이고, 그 뒤 이렇게 말한다:

> "pull하기 전 상태로 돌아왔어요. 내 커밋 {n}건은 내 컴퓨터에 그대로, 동료 커밋 {m}건은
> 팀 저장소에 그대로 있습니다. **아무것도 잃지 않았어요.**"

## 절대 하지 않는 것

- rebase 이어가기(`--continue`) — 취소만 한다.
- 소스 파일 전체를 `--ours` / `--theirs`로 통째로 고르기 (잠금 파일만 예외).
- 사용자에게 보여주지 않고 조각 결정하기.
- 충돌 표시가 남은 채로 커밋하기.
- force push, `reset --hard`, `--no-verify`.
